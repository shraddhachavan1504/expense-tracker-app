Buttons with a brain.

Two buttons, one motion system, built for the expense tracker capstone. Click each to trigger a fake async call — 20% of attempts fail on purpose.

Duration & easing notes

Hover and press use 160ms with a standard ease — fast enough that the button feels immediately responsive to the cursor, never floaty. State-to-state crossfades (idle → loading → success/error) run at 260ms: slow enough to read as intentional, fast enough not to make the user wait on the animation itself. The checkmark draw-on is the one slow beat, 420ms with an ease-out-back curve, because a success state is the one moment worth a tiny flourish — everything else stays purely functional. The button's box (210×52) never changes size; every state lives in the same CSS grid cell and crossfades via opacity and transform only, so nothing else on the page ever reflows. Error introduces a single 380ms shake (skipped under prefers-reduced-motion, where the button relies on its color and icon change instead, never on shake alone). One deliberate exception to the four-color system: an off-palette coral (#FF5C7A) marks the error state, because reusing cobalt or signal yellow for "something went wrong" would work against how people already read those colors elsewhere on the page.
